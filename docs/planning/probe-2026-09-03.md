## 1. תקציר מנהלים

שלושת המקורות של Kafka — Jira, Confluence, git — **נגישים במלואם ואנונימית**. שתי תגליות משנות-תכנון:

1. **`/rest/api/2/search` עם `expand=changelog` מחזיר את ה-changelog המלא, לא מקוצץ.** אימתתי מול `/issue/{key}`: issue עם 113 histories החזיר 113 גם ב-search. גם ה-comments מלאים (33/33). המשמעות: **אין צורך ב-fetch לכל issue בנפרד** — 1,416 issues יורדים ב-~15 קריאות במקום ~1,400. זה מוריד את זמן ה-harvest מסדר גודל של שעה לדקות.
2. **Confluence CQL search תומך ב-`expand=body.storage`** — 25 גופי דפים מלאים בקריאה אחת. כל 1,391 דפי ה-KIP יורדים ב-~56 קריאות.

**Azure DevOps נופל.** אין גישה אנונימית ל-work items באף אחד מארבעת ה-orgs שנבדקו. הוא יורד מהתכנית.

**GitHub REST API לא שמיש** ללא token (60 בקשות/שעה). אבל הוא גם לא נחוץ: 98.7% מה-commits נושאים `(#PR)` בכותרת, כך שקשר Commit→PR מופק מהטקסט בלי API.

## 11. שלושה סיכונים ל-שלב ה-harvest

1. **זיהוי כפול של אנשים (identity resolution).** git הוא מקור הרעש: 79 שמות עם יותר מ-email אחד, 29 emails עם יותר משם אחד, 690 זוגות מול 607 שמות. ב-Jira יש collision אחד ב-`displayName` ("Pritam Kumar" → שני usernames). **הפחתה:** לעגן כל `Person` ב-ASF username בלבד (Jira `assignee.name` = Confluence `createdBy.username`); לחבר commits לאנשים **רק** דרך מפתח ה-issue בהודעה, לעולם לא דרך שם/email; לרשום כל מיזוג ב-`unmapped_fields` לביקורת.

2. **Mentions מזויפים מתבניות.** ה-placeholder `KAFKA-1` בתבנית ה-KIP הופיע ב-16% מדגימת הדפים; אם ייקלט, ייווצר hub מזויף שיעוות community detection ו-PageRank. **הפחתה:** blacklist ל-`KAFKA-1`; אימות כל issue key מול allowlist שנלמד ב-harvest (כפי שכבר מחייבים ה-conventions); ספירת mentions לכל key ובדיקה ידנית של החריגים העליונים לפני ה-load.

3. **קישוריות דלה מדי בשכבה הדטרמיניסטית.** רק 19–43% מה-issues נושאים issuelink פורמלי, ורק 46–71% נמצאים ב-git. הרכיב `clients` הוא החלש ביותר (19% קישורים, 0.21 ל-issue). אם שכבת ה-LLM לא תוסיף קשרים אמינים, הגרף עלול להתפרק לרכיבים מנותקים ולפגוע ב-multi-hop retrieval. **הפחתה:** למדוד connectivity (גודל הרכיב הקשיר הגדול, התפלגות degree) מיד אחרי ה-load הדטרמיניסטי ולפני שכבת ה-LLM, ולקבוע סף מראש; לנצל את 27–29% ה-issues שמזכירים issue אחר **בטקסט בלבד** — זה ה-upside הגדול ביותר ל-mentions דטרמיניסטיים.

### הערות תפעוליות ל-harvest

- **חובה:** `component = "connect"` במרכאות ב-JQL.
- `maxResults` מקסימלי = 1000; לדפדף עם `startAt`.
- `expand=changelog` ב-`/search` — לא צריך fetch לכל issue.
- Confluence: `expand=body.storage` על ה-CQL search, `limit=25`.
- Jira מחזיר את שני צדי ה-issuelink (`inwardIssue`/`outwardIssue`) — לקפל ל-edge אחד ב-load.
- אין צורך ב-GitHub token: מספר ה-PR נמצא בכותרת ה-commit ב-98.7% מהמקרים.
