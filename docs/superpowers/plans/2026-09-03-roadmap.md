# מוח ארגוני Graph RAG — Roadmap של תכניות המימוש

Spec: [`../specs/2026-09-03-org-brain-graph-rag-design.md`](../specs/2026-09-03-org-brain-graph-rag-design.md)

עיקרון: ארבע תכניות, כל אחת מייצרת תוכנה עובדת ונבדקת בפני עצמה. **רק Plan 0 נכתבת מראש במלואה.** כל תכנית הבאה נכתבת לפרטים רק אחרי שהקודמת הסתיימה — כי היא תלויה במספרים אמיתיים (זמינות Jira, צפיפות קישורים, גודל קורפוס, איכות חילוץ). זה לא דחיינות: לכתוב היום את פרטי ה-extract בלי לדעת כמה chunks יש = ניחוש.

## תבנית לכל שלב בתוך תכנית (מהספק, סעיף 6.3)

1. Brief ב-`docs/planning/steps/NN-<step>.md` (המתכנן)
2. Dispatch לסוכן הנדסה (Opus) — או לסוכן-LLM דרך batches
3. Execute → `data/reports/<step>.json` + דוח יציאה
4. `brain-reviewer`
5. accept / fix / שינוי תכנית → `docs/planning/progress.md`
6. `lesson-writer` → המתכנן מסיים `docs/lessons/NN-<step>.md` ומציג למשתמש
7. commit

## מה המשתמש לומד בכל תכנית

- **Plan 0:** איך נראית תשתית Graph RAG מקומית מלאה; למה embeddings מקומיים; מה עושה GDS; איך מגבילים סוכן פיזית (כלים) במקום להסתמך על פרומפט.
- **Plan 1:** קונקטורים עמידים; מודל קנוני כמפתח ל"כל מערכת"; כמה מהגרף נבנה בלי LLM; סכמה-קודם; entity resolution במספרים; קהילות.
- **Plan 2:** ששת דפוסי האחזור מבפנים; Text2Cypher כמשטח תקיפה; Agentic GraphRAG דרך MCP; provenance כמוצר.
- **Plan 3:** מדידה בשכבות; baseline הוגן; "מתי מה" במטריצה; עלות/latency; מתי לא גרף.
